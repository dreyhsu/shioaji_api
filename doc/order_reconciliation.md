# 委託與結案管理

Dashboard 的「委託與結案管理」入口位於圖表頁頂端，網址為 `/orders`。

本頁整合完整本機管理單、券商已保存的外部委託、券商觀測中的進出場委託、曲線進場條件及持久化指令。已到期合約、已結案單與超過最近 30 筆的紀錄都可以查詢。

## 查看差異

- 「待處理」包含等待中的曲線及未知執行結果，不受日期篩選限制，避免漏掉較早的阻擋。
- 「全部委託」可以依日期、商品、來源、方向、進場／平倉、券商狀態及本機結案狀態篩選，並搜尋本機 ID、券商 ID、seqno／ordno。
- 「部位與結案」列出本機剩餘口數、外部已平與本機結案標記。券商委託結束不代表成交部位已平倉；取消餘量也不會結束已成交部位的保護。
- 「曲線進場／交易指令」可以找到沒有券商委託的本機條件或指令。指令最初的 `unknown` 結果會保留，後續解決另有核對紀錄。
- 「處理紀錄」保存操作、發起／完成時間、原狀態、證據、人工說明與結果。

頁面頂端顯示正式／模擬／Mock 環境、帳戶遮罩、交易服務狀態及最後核對時間。交易閘門仍由 trade 判斷；歷史缺棒不會藉本頁改變有效 tick 出場規則。

券商來源是既有 session 的委託與部位快照，不代表券商所有歷史都可取得。已保存的舊外部紀錄仍列出，資料不全、快照截斷或查無原委託時明示範圍；不能把單次查無資料當成從未下單。每批最多保存 2,000 筆券商委託，超過時標記截斷並停用依賴完整證據的處理，避免大批歷史阻塞交易。

## 處理步驟

1. 點「重新核對券商」。trade 沿用原 session 查詢與同步，不另登入；主動查詢間隔至少 5 秒，並沿用 `order_sync_seconds`。
2. 從待處理清單開啟紀錄，查看券商證據、本機欄位、關聯及時間軸。
3. 選擇處理方式，按「查看處理預覽」。預覽顯示環境、目標、效果與券商操作。
4. 核對後按「確認執行此處理」。預覽有效期 2 分鐘；套用前重新讀取券商資料，委託、成交、部位、身分或 session 變動時需重新預覽。
5. 查看最終結果與剩餘阻擋。處理完成不自動重啟曲線，也不開新倉。

可用處理方式：

| 操作 | 適用情況 |
|---|---|
| 取消等待突破 | 曲線仍為 `armed`，沒有進入送單 |
| 撤銷券商未成交餘量 | 已確認帳戶、唯一書號及餘量的系統／外部掛單；部分成交繼續管理 |
| 人工核對無委託 | 舊曲線或指令沒有管理單 claim、SDK 送單證據或矛盾券商紀錄，且使用者確認已查核 |
| 關聯原曲線委託 | 原指令與管理單有可靠、唯一關聯，原委託結果已確認 |
| 人工配對原進場／平倉 | 管理單結果不明；使用者填寫券商 ID、seqno、ordno、已核對交易日與說明，商品、方向、口數、帳戶及成交證據全部相符 |
| 解決原未知指令 | 原管理單已有已確認結果，或撤單／修復有可驗證終態；原指令不改為可重跑 |
| 同步委託及部位 | 沿用既有券商權威核對與外部平倉／接管規則，不補造成交或猜測分配 |

人工核對的說明至少 10 字；無委託核對的交易日須與原紀錄的已驗證交易日一致。存在送單 claim 時，不能單靠確認框清掉；有矛盾、歧義或缺少證據會列出原因，保留阻擋。

「撤單已送出」不等於已取消。券商未回終態時顯示等待確認；撤單回覆遺失則保存未知結果，不自動再撤。成交與撤單競態依券商終態核對。

## 逾時、重啟與證據

瀏覽器以環境、DB 與訊號商品隔離保存待確認操作及唯一 ID。逾時只查原 ID；查無原 ID 且使用者按「沿用原 ID 重試」時，才用相同內容重試。`unknown` 仍可查看、重新核對與提出另一個修復操作，但不重送原券商操作。

`trade_reconciliation_previews` 保存預覽與已使用的 command ID；`trade_reconciliation_events` 保存追加處理證據；`trade_reconciliation_resolutions` 另外關聯已核對的事項。原指令與 claim 不刪除，重啟不重送。`broker_observation_batches`、`broker_order_observations`、`broker_order_observation_history` 保存資料範圍與委託變化，帳戶僅保存雜湊，不保存 SDK 原始物件或任意例外全文。

人工身分配對不重播歷史成交通知，既有逐單風控與最高浮盈追蹤保留；新增預設仍遵循 0.5 倍 1h ATR 停損與 2 倍停利。未平部位不能靠本機結案標記隱藏。

純核對／預覽查詢失敗保留既有資料，使用安全的錯誤分類，不當作可能送出券商委託的未知結果；此類查詢不會單獨新增送單阻擋。真正撤單與套用結果不明仍須核對。

Dashboard 的清單／詳情 GET 不登入、不查券商、不初始化 schema。券商查詢、撤單與修復都經 `TradeClient → /api/commands`，由 trade 原背景執行緒執行。日常觀測保存安排在已接受指令與出場保護之後；GET 不將完整歷史塞進交易快照。

## 離線驗證與版本生效

使用 conda `tss` 執行：

```powershell
conda run --no-capture-output -n tss python -m pytest src/test_order_reconciliation.py -q
node tools/test_orderdesk_ui.cjs
```

可執行 `conda run --no-capture-output -n tss python tools/preview_order_desk.py` 開啟 `http://127.0.0.1:8779/orders`。這是獨立暫存 DB、初始暫停的 Mock 預覽，含合成的 #46 待核對條件及 37 筆歷史；不讀正式 DB、不登入券商、不傳 Telegram。Ctrl+C 停止該預覽。

正式頁面需依既有協作流程正常重啟 Dashboard／trade 後生效。此次開發不啟用正式新版本、不送出或撤銷正式委託。原生瀏覽器版面、macOS 與券商現場流程仍須另行驗收。
