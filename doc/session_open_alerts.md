# 開盤跳空後穿越開盤價：Telegram 提醒

## 規則

由訊號商品的 monitor 判斷，商品取自 `config/runtime.json` 的 `signal_code`（目前為 TMFR1）。日盤 08:45、夜盤 15:00 使用 Asia/Taipei 時間，實際時段與上一時段依交易日曆確認，包含週末及假日。

| 開盤前已收定 1h Supertrend | 本時段開盤 | 提醒條件 |
|---|---|---|
| 空頭 | 高於上一時段末根完整 1m 收盤 | 完整 1 分 K 收盤跌破開盤價，提示偏空觀察 |
| 多頭 | 低於上一時段末根完整 1m 收盤 | 完整 1 分 K 收盤漲破開盤價，提示偏多觀察 |

- 標準 1h Supertrend 使用 ATR 10／倍數 3，與 Dashboard 的 1h 指標一致。開盤方向不使用開盤後才收定的小時 K，也不使用 Supertrend AI。
- 開盤價取 08:45／15:00 第一根完整分鐘 K 的 open；不能用較晚第一根 K 代替。上一時段必須有完整分鐘資料。沿用專案邊界：日盤最後分鐘為 13:44，夜盤為 04:59，不等同交易所結算價。
- 不額外設定最低跳空點數或穿越緩衝。僅碰到開盤價、盤中穿越後收回都不提醒。
- 第一根即可觸發；例如 08:45 的 K 棒在 08:46 收定，經同步及健康檢查後提醒。之後必須是同時段相鄰完整分鐘由開盤價另一側穿越，不能跨缺棒比較。
- 等待期間已收定 1h Supertrend 翻向，或應有的小時趨勢無法確認，就取消原訊號，翻回也不重新啟用。等待至本時段結束；末根分鐘有收盤後 60 秒的正常同步／通知窗口。
- 僅建立 Telegram 觀察提醒，不建立委託、不啟用進場，不更動任何停損或交易規則，也不新增券商 session／訂閱。

## 設定與生效

`config/alerts.json`：

```json
"session_open_supertrend": {
  "enabled": true
}
```

首次安裝程式後需重啟訊號商品的 monitor，才會建立所需資料表及載入功能；本次開發沒有自動重啟正式服務。之後規則開關可熱載入，沿用 `telegram_enabled` 總開關及程序的 `--no-telegram`。Mock 不啟用此提醒。

不需要變更原 Telegram 憑證。通知由既有 `MonitorNotifier` 背景傳送，不讓 HTTP 阻塞行情同步。每商品／模式／時段／規則版本最多建立一筆提醒 claim，日盤與夜盤各自計算；沿用既有傳輸重試及結果紀錄，不另加歷史重送佇列。

## 重啟、暫停與修復

- unified DB 的 `session_open_alert_states` 保存開盤依據、上一時段、趨勢、分鐘游標、資料版本、狀態、原因與觸發分鐘。狀態與 `telegram_alerts` claim 一起提交，之後才交給背景發送。
- 重啟時無通知地重建已發生的事件；若先前尚未觸發，可繼續等待啟動後的新穿越。已觸發或取消的同時段不重新啟用。
- 總開關／規則停用、`--no-telegram` 或行情不健康時仍觀察並消耗穿越。恢復當輪不補發期間事件。
- 只發送收定後 60 秒內的新事件。缺開盤分鐘、上一時段資料或有效 ST 時不猜測；回補先無通知地重建，再等待之後的新訊號。
- 已處理分鐘或小時資料修訂時，重建過程不發通知；開盤價格／參考收盤／開盤 ST 依據被改動時，等待中的訊號失效。已發提醒保留當時依據，不因修訂重新發送。
- DB 中 `triggered` 表示條件已發生並被消耗，不代表 Telegram 已送達；查詢 `telegram_alerts.ok`：NULL 為未確認、1 為傳輸回報成功、0 為未發送／失敗。

## 離線驗證

新增測試位於 `src/test_session_open_alerts.py`，使用真實 Supertrend／日曆計算、暫存 SQLite、假的通知傳輸與受控時間。測試不登入券商、不呼叫外網、不發真實 Telegram。

```text
conda run -n tss python -m pytest src/test_session_open_alerts.py -q
```

Windows 如遇共用 pytest 暫存目錄權限問題，可使用新的獨立 `--basetemp`。macOS 原生及實際行情／Telegram 端驗收仍需另行完成。
