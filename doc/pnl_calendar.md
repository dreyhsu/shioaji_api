# 損益月曆

Dashboard 頂端的「損益月曆」開啟 `/pnl-calendar`。這是同一服務的新頁面，不需要另一個啟動程序或券商連線。更新後，於既有服務停止並釋放程序鎖後，照原方式重啟 Dashboard 與 trade；不要另開第二份券商服務。Mock 僅重啟 Dashboard 即可。

## 操作與統計

- 上一月／下一月／本月切換月份，可按實際月份合約篩選；初始為全部合約。
- 頁首顯示當月已實現毛損益、平倉訂單數、平倉口數。金額為 TWD，未扣手續費、交易稅，不包含未平倉浮動損益。
- 獲利為綠色、虧損為紅色；有交易且損益為零，與「無平倉」格不同。點日期查看該日各筆平倉成交。
- 依 Asia/Taipei 實際平倉成交日期歸日，不採期貨交易日。凌晨 01:00 的成交歸當天。
- 分批平倉分次認列；每日「筆數」是當天有平倉的原始訂單數，月筆數則在全月去重，因此每日筆數相加可能高於月筆數。口數是已成交平倉數量。
- 多單毛損益＝（該批平倉成交價－進場加權成交均價）× 該批口數 × 契約乘數；空單價差反向。
- 僅包含本系統 `managed_orders` 管理的交易，包含系統內手動及自動進場；券商 App 或其他程式下的單不在此統計範圍。
- 可見頁面每 60 秒更新，切回頁面及「重新整理」也會更新。顯示時間為成交明細最近一次實質變更時間，不代表券商即時連線狀態。

## 資料品質與歷史限制

`pnl_fills` 保存券商確認的逐筆進出場成交。`pnl_order_metadata` 保存該訂單的契約乘數、幣別及明細完整性狀態，由既有交易背景執行緒寫入統一 DB。月曆 API 只讀 DB，不登入、不同步券商、不讀 acquisition DB，也不會寫入資料表。

必須具有完整進場成交明細、已終結的進場狀態、與累計口數相符的平倉明細、可靠成交時間／價格及 TWD 契約乘數才會認列。尚未取得可靠資料的訂單整筆排除，並列入「歷史資料不完整」數量；此數量涵蓋所選合約的全部歷史，**不一定屬於所選月份**。沒有可靠日期，無法安全把缺漏紀錄分配到月份。

舊資料不以 `updated_at`、`triggered_at`、委託價或風控觸發價估算。若既有 trade 同步所得的委託快取仍有完整成交，可在背景恢復，包括已平倉的非 active 訂單。券商快取已不含的歷史明細不會自動補造，也不額外查詢帳戶全部損益。

同一委託的成交明細以累計快照原子更新，優先以券商 `seq` 識別；缺少識別時使用完整成交內容與重複次數保留同價同時多筆成交。重複同步、程序重啟、稍後補齊時間或識別皆不重複認列。缺時間或口數不符時等待後續可靠同步。

月曆寫入失敗不回滾已確認的委託狀態、不停止出場保護；印出安全的錯誤型別，資料不完整時不計入。原有交易與下單規則不變。

正式與模擬依 runtime 與訂單 simulation 欄位隔離；Mock 使用獨立暫存 DB、回放日期及明確的假契約乘數（10）。Mock 重設也清空月曆明細。頁面不提供模式切換。

## 維護位置與 API

- `src/pnl_calendar.py`：成交明細規格、保存、計算、月份／日期查詢及頁面路由。
- `src/web/pnl_calendar/index.html`、`calendar.js`、`style.css`：獨立畫面、互動與樣式，不依賴原圖表或交易控制腳本。
- 原 Dashboard 僅掛載 router／注入 DB、模式、時鐘與 Mock 鎖，並提供入口；`db.init_schema` 建立新增資料表，`TradingService` 提供成交寫入掛點。一般月曆修改只需處理上述專用模組。

唯讀端點：

- `GET /api/pnl-calendar?month=YYYY-MM&contract_code=...`：月份摘要、每日統計、可選合約、模式、資料完整性與最近更新時間。
- `GET /api/pnl-calendar/day?date=YYYY-MM-DD&contract_code=...`：當日摘要與逐批平倉明細。

`contract_code` 可省略。錯誤日期回 422；資料庫無法讀取回 503。每次回應使用同一讀取快照。舊 DB 尚無月曆資料表時回 `ledger_available=false`，GET 不建表；由服務正常初始化建立。頁面遇讀取錯誤時清除舊結果並顯示錯誤，不呈現為零損益。

## 驗證

在 macOS 或 Windows 使用 conda `tss`：

```text
conda run -n tss python -m pytest -q src/test_pnl_calendar.py
```

測試涵蓋多空、加權成本、分批／跨日／跨月、同時同價成交、重複同步與重啟、遲到明細、缺資料、模式與合約篩選、舊 DB 唯讀、Mock 重設及明細寫入故障隔離。

Windows 原生畫面與實際券商成交欄位／金額一致性仍須在部署環境驗收；離線測試不代表已完成券商驗收。
