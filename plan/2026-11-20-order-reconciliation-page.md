# 委託與結案管理頁規劃

日期：2026-11-20（Asia/Taipei）。狀態：規劃完成，尚未實作、部署或操作正式委託。

## 目標與範圍

新增 Dashboard 獨立頁 `/orders`，入口名稱「委託與結案管理」。使用者可以查閱系統送單、券商 App／其他外部來源委託、實際剩餘部位，以及本機是否結案；遇到影響下單的紀錄，可在頁面查看原因、核對證據、預覽處理結果並執行處理。

本頁包含四類對象：券商委託、管理部位、尚未送單的曲線進場條件、持久化交易指令。後兩類即使沒有券商委託，也必須可以單獨查到並處理。

「所有」定義為本專案 DB 已保存的完整歷史，加上目前帳戶可從券商取得的委託／成交／部位；不沿用目前最近 30 筆的限制。未配置行情的商品、到期月份及已結案紀錄也可查閱。券商能取得的歷史範圍、尚未保存的舊資料及查詢失敗須明示，不能宣稱資料完整，不能將「這次查不到」當成「從未委託」。

沿用現有交易帳戶與模式，正式／模擬分開。外部委託若無可靠來源欄位，顯示「券商外部委託」，不推定一定由 App 下單。未配置商品可唯讀顯示，策略接管仍須符合原行情配置與核對規則。

## 現況與缺口

- `TradingService.orders()` 僅回傳最近 30 筆 `managed_orders`；目前快照不是完整歷史查詢 API。
- `managed_orders` 保存本機管理與進出場狀態；`broker_external_orders` 保存外部委託；`broker_order_identities` 保存券商身分對應。
- `curve_entries` 的 `armed`／`submitting` 會阻擋再次啟用曲線；現有取消只處理 `armed`。
- `trade_commands` 的 `unknown`、管理單的未知進場／出場 claim，以及部位核對差異，會各自影響交易閘門；頁面不能只看管理單的 `active`。
- 外部部位與成交修正已有 `position_sync_events`、`external_close_reconciliations`、`order_reconciliations` 等證據；新頁應整合展示。
- 2026-11-19 的曲線進場 #46：本機停留 `submitting`，沒有關聯管理單與送單事件，使用者人工確認券商無此委託後才結束。證據已保存於 `data/recovery/curve-entry-46-manual-reconciliation-20261119-213522.json`。新頁應能完成同類流程。

## 頁面配置

### 頂端：目前可否下單與資料時間

顯示正式／模擬環境、帳戶遮罩、trade 服務狀態、最後成功券商核對時間、查詢涵蓋範圍及快照是否過期。提供「重新核對券商」與「查看處理紀錄」。

分開顯示手動進場、曲線進場、各部位出場保護的狀態。每項阻擋列出具體原因、關聯紀錄與處理入口，例如：

> 曲線進場暫停：曲線進場 #46 送單結果待核對。查看紀錄 → 核對並處理。

處理完成後重新計算全部阻擋，顯示「此項已解除，仍有 1 項待處理」或「目前可啟用」。行情過舊、排程外、未配置商品等狀態也要明確列出，但不能透過結案動作解除。

### 中段：清單與篩選

分頁：`待處理`（預設）、`全部委託`、`部位與結案`、`曲線進場／交易指令`、`處理紀錄`。

篩選包含交易日區間、商品／月份、系統／外部來源、買賣方向、進場／平倉、券商狀態、本機結案狀態、影響下單與否。可搜尋本機 ID、指令 ID、券商 ID、seqno／ordno。採分頁載入，不能因預設日期範圍漏掉更早尚未解除的阻擋。

清單欄位：

| 欄位 | 顯示內容 |
|---|---|
| 時間／交易日 | 分開呈現委託時間與交易日；只有日期時標示「僅交易日」 |
| 來源／類型 | 系統手動、已確認的曲線進場、券商外部；進場／平倉／條件／指令 |
| 商品與方向 | 實際月份合約、買／賣、已確認倉別 |
| 口數 | 委託、成交、已撤、未成交餘量；部位另列實際剩餘與外部已平 |
| 券商狀態 | 未成交、部分成交、全成、已撤、拒絕、未知；附核對時間 |
| 系統狀態 | 等待條件、管理中、待核對、委託已結束、部位已結案 |
| 結案與影響 | 是否結案、結案依據、影響哪個交易閘門、剩餘保護是否運作 |
| 操作 | 查看、核對、撤銷未成交餘量、處理本機紀錄，依對象顯示 |

券商委託和其已接管管理單依可靠身分建立關聯，避免重複統計。進出場委託、部分成交及後續平倉保留各自紀錄；有歧義的對應明示待核對。

### 詳情：券商、本機與時間軸

左側顯示券商證據，右側顯示本機狀態與保護設定，下方顯示啟用條件、送單、成交、撤單、外部同步、人工修正與結案時間軸。沒有值時顯示缺少，不用觸發價冒充成交均價。

關聯鏈涵蓋 `指令 → 曲線條件 → 進場委託 → 管理部位 → 平倉委託 → 核對／結案`。舊資料缺關聯時明示無法唯一對應，不能只憑時間接近自動配對。

## 狀態與操作規則

「券商委託已結束」「部位已平倉」「系統結案」「待核對事項已解決」分開記錄。取消未成交餘量不會把已成交部位結案，標記本機事項已解決也不會取消券商掛單。

| 情況 | 頁面可做的處理 | 完成條件與結果 |
|---|---|---|
| 曲線仍等待突破，尚未送單 | 取消等待進場 | 結束該條件；不觸碰券商部位 |
| 系統或外部有可確認掛單 | 撤銷未成交餘量 | 再核對帳戶與唯一委託身分，沿用原 session 撤單；收到券商確認才顯示已撤 |
| 部分成交後撤餘量 | 撤銷剩餘掛單 | 保留成交帳、剩餘部位及原風控，不能整筆結案 |
| 券商已撤／拒絕，本機仍掛單中 | 核對並同步終態 | 保存券商證據；沒有持倉及未明出場才結束對應管理紀錄 |
| 券商已有成交，本機曲線／指令仍待確認 | 核對並關聯既有委託 | 唯一配對後更新關聯；不再送一張單 |
| 外部部分／完整平倉，本機尚未同步 | 核對並同步部位 | 沿用現有批次與明細規則；部分平倉只管理剩餘，全平才結案 |
| 本機已結案，但券商仍持有同一批次 | 核對並修正管理狀態 | 沿用最新券商優先規則，保存修正證據與既有風控 |
| 舊條件／指令結果不明，人工確認無委託 | 人工核對並結束待確認事項 | 填入核對範圍與說明，檢查既有關聯與衝突，保存證據後終結該事項；不自動重啟條件 |
| 有送單 claim／無法唯一配對／證據矛盾 | 補證據、選擇候選後重新驗證 | 不能以「沒有查到」或一般確認框清除；維持待核對並列出欠缺資料 |

人工處理不是通用「強制結案」按鈕。特別是券商還有部位、仍有有效掛單或存在未明出場時，不能藉本機標記讓它消失或停止保護。第一版不增加市價平倉功能；需要平倉時顯示既有受控操作入口或券商 App 核對指引。

## 使用者操作流程

1. 開啟頁面，從「待處理」點選阻擋項目，查看券商與本機差異。
2. 「重新核對券商」建立持久化查詢指令，由 trade 背景處理，畫面顯示查詢中／完成／失敗與涵蓋範圍。
3. 選擇適用的處理方式，系統產生預覽：原狀態、新狀態、關聯對象、證據、券商操作、剩餘口數與保護、預期解除哪個阻擋。
4. 若需人工確認，表單明列日期、商品、方向、口數、委託書號或缺少的身分，要求填寫確認結果與說明。附件若列入後續版本，須提供遮罩提示，避免保存帳戶與憑證。
5. 使用者確認後送出唯一 ID 的處理指令；trade 在執行前再次檢查資料版本及券商現況。預覽後發生成交或同步變動，拒絕舊預覽並要求重新核對。
6. 顯示最終結果、處理證據與剩餘阻擋。逾時查原指令，不能換新 ID 重送；也不因修復成功自動送新單或重啟舊曲線。

撤單確認畫面必須標示「會向券商撤銷 X 口」；本機紀錄修正必須標示「只更新系統紀錄」。送出撤單後若只回 Submitted／待確認，維持待確認；撤單與成交競態依最終券商回報核對。

## 技術設計

### 讀取與交易閘門

- Dashboard 保留無券商登入架構。新頁 GET 讀 unified DB 的持久化查詢資料與 trade 背景快照；顯示各自版本和成功核對時間，不呼叫券商。
- 新增按日期與游標分頁的歷史讀取 API；不要將完整歷史加入每 0.5 秒的交易快照，也不要逐筆調用會重算全部曲線的 `_public_order()`。
- trade 背景保存可供頁面查閱的券商委託觀測資料與查詢涵蓋資訊；未配置商品可供診斷，不能因此新增行情訂閱／登入或加入策略。
- 集中產生 `blockers`：穩定 ID、對象類型／ID、原因、影響範圍、證據時間、允許的修復動作。UI 與後端交易閘門共用同一判定，不由前端猜測。
- 手動核對／修復可在新增委託被禁止時提出，否則會形成「要先可下單才能解除阻擋」的循環。每種修復仍有自己的身分、來源、版本與證據檢查，不藉此開放一般送單。
- 修復不能解除行情、模式、世代、排程、其他未知指令等無關閘門。出場保護維持有效 tick 規則，曲線進場維持相鄰完整收定 1 分 K。

### 指令與持久化

擴充現有 `/api/commands`，初步新增 `refresh_reconciliation`、`preview_reconciliation`、`apply_reconciliation`；撤單依對象重用或擴充 `cancel_entry`，取消曲線沿用 `cancel_curve`。具體 payload 於實作前定稿。

- 所有券商 I/O 與修復由既有 trade 單一背景執行緒執行，不新增 session／worker。大量歷史查詢分批、節流並有上限，維持行情載入、曲線檢查、已接受指令及有效 tick 出場的原處理順序。
- 預覽保存 proposal ID、動作、目標、完整變更內容摘要、預期版本、證據版本與有效期限。套用時比對；期限內資料改變仍拒絕舊預覽。
- 新增追加式 `trade_reconciliation_events`：處理 ID、唯一 command ID、對象與關聯 ID、操作、發起／完成時間、環境與 trade instance／generation、操作者或確認來源、人工說明、證據、修正前後、完成結果。
- 預覽和歷史查詢的工作進度持久化，與一般送單結果分開；工作失敗不清空已有券商資料，不將空結果誤當完整歷史。
- 保存券商觀測批次與個別委託觀測歷史，含查詢成功範圍與身分；避免只覆寫最新摘要後遺失人工核對依據。詳細保留量與清理政策於實作時確認，未結事項與修復證據不可先刪。
- 原始 `unknown` 指令與送單 claim 不刪除、不改成可重跑。另建明確 resolution 關聯，所有閘門統一辨識已核對解決的事項；同 ID 讀取仍回原執行結果並附後續核對結論。
- 修復在短 DB 交易中比較目前版本、原子保存帳務變更及稽核，不持有 DB 寫鎖等待券商。相同處理重送或重啟不會再次撤單、重複歸帳或重播成交通知。
- 剩餘口數沿用既有核對函式；`exit_filled_quantity` 與 `external_exit_quantity` 的累計關係必須按現有定義處理，不能自行相加重複扣減。
- 既有已保存風控保留。新增單的預設固定停損為 0.5 倍 1h ATR、停利 2 倍；人工修復不趁機批次改價，也不補造缺失 ATR。

### 建議變更位置

- `src/web/orders.html`、`src/web/orders.js` 與頁面樣式：新頁、篩選、明細、預覽與確認。
- `src/dashboard.py`／`src/trade_client.py`：入口、唯讀查詢與持久化指令代理。
- 新模組 `src/order_reconciliation.py`：查詢視圖、阻擋項目、預覽與修復規則。
- `src/trade.py`／`src/trading_models.py`：命令、進度與 request 驗證。
- `src/db.py`：必要資料表、索引與相容 migration。
- `src/trade_service.py`／`src/curve_entry_controller.py`／`src/broker_sync.py`：串接核對及可靠身分鏈，不在 Dashboard 直接更改交易狀態。

## 第一版交付與驗收

第一版需包含完整本機歷史、現有券商可取得資料、阻擋原因、曲線等待取消、已管理／外部掛單撤餘量、券商終態與部位同步、人工核對結束舊事項，以及追加處理紀錄。預覽和證據是可操作版本的一部分，不能只先交付清單後仍要求手改 DB。

分階段實作，但完整驗收後才視為本需求完成：

1. 建立查詢視圖、歷史分頁與阻擋模型，驗證數量及關聯。
2. 建立預覽／套用、核對證據與各類處理規則，完成隔離測試。
3. 製作頁面並串接，涵蓋載入、空資料、過期、未知與錯誤狀態。
4. conda `tss` 離線測試及 Windows 原生頁面驗證，另做 macOS 相容檢查；正式更新依既有協作停止／啟動流程進行。

主要驗收案例：

- 超過 30 筆、已到期月份、已結案單、外部掛單／平倉單均能搜尋；查詢涵蓋不足明示。
- 重現 #46，使用者核對無委託後，可在頁面預覽並結束舊事項；舊證據保留，解除曲線鎖且不自動進場。
- 實際已送單但回覆遺失時，保留未知 claim；唯一配對後連結原委託，不重送。僅查不到／僅勾選確認不能誤清有效 claim。
- 部分成交 2 口中 1 口後撤餘量：只撤 1 口，已成交 1 口繼續管理與保護。
- App 平倉掛單可查閱，不能當新倉接管，也不重複發保護平倉。
- 外部部分平倉保留原風控與追蹤；完整平倉與已結案但券商仍持有的同批次差異，依唯一明細同步並保留修正證據。
- 指令 `unknown`、曲線 `submitting`、管理單未知出場等不同層級，修復後仍正確列出其他阻擋。
- 預覽後發生成交、重複提交、HTTP 逾時、程序重啟、DB 寫入失敗不造成誤結案、重送或半套修復。
- 讀取頁面、重新整理及切分頁不登入或查券商；主動核對沿用原 session 並節流，過期快照不能執行變更。
- 測試用暫存 DB 與假券商，不為驗收額外送正式測試單、撤真實掛單或傳送歷史通知。

## 暫不納入第一版

任意刪單／強制忽略券商部位、一鍵解鎖全部、新增帳戶登入、批次強制結案、CSV 匯入人工補造帳務，以及從本頁直接開新倉或市價平倉。

後續可依需求擴充唯讀匯出與遮罩附件；不影響第一版在介面完成核對與解除已確認舊事項的目標。
